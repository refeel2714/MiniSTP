# STP-5200 결재 권한

> 이 문서는 `src/ministp/ui/screens/STP-5200.yaml`에서 생성돼요. 직접 고치지 말고 화면 정의를 고친 뒤 `python scripts/gen_screen_docs.py`를 실행하세요.

분류: 운용 통제 > 결재 권한

## 목적

누가 주문을 쓰고 승인할 수 있는지 정해요(R-99, R-102). 왼쪽에서 사용자를 고르면 그 사람의 권한 이력이 오른쪽에 나와요. 권한은 고치지 않고 부여·회수할 때마다 한 줄씩 쌓여서, 어느 날 누가 승인 권한이 있었는지 언제든 다시 볼 수 있어요. 계좌를 정한 줄이 모든 계좌 줄보다 앞서요. 승인 권한에는 1건 한도와 셀프 승인 허용을 붙여요. 셀프 승인 허용이 없으면 자기가 쓴 요청은 다른 승인자가 승인해야 해요. 사용자 ID는 지금 PC 로그인 이름이고(화면 서버를 띄운 사람), 처음 한 사람은 누구나 등록해 자기에게 권한 관리를 줘요. 그 뒤로는 권한 관리자만 바꿔요.

## 화면 구성

좌우 구성이에요. 왼쪽 목록에서 행을 고르면 오른쪽이 그 행의 상세로 바뀌어요.

- 왼쪽 (너비 44%): `users` 사용자
- 오른쪽: `rights` 권한 이력

## 트랜잭션

| 트랜잭션 | 이름 | 조회조건 | 쓰는 그리드 |
|---|---|---|---|
| `STP5200R01` | 사용자 | 없음 | users |
| `STP5200R02` | 권한 이력 | `user_id` (text) | rights |

## 처리 트랜잭션

처리 버튼이 부르는 트랜잭션이에요. CLI 명령과 같은 함수를 부르고, 화면 서버를 처리 가능으로 열었을 때만 동작해요.

| 트랜잭션 | 이름 | 입력 | 부르는 버튼 |
|---|---|---|---|
| `STP5200U01` | 사용자 등록 | `user_id` (text), `name` (text) | users · 사용자 등록 |
| `STP5200U02` | 권한 부여 | `user_id` (text), `right_code` (text), `account_id` (text, 선택), `max_order_value` (int, 선택), `self_approve` (bool, 선택), `effective_from` (date, 선택), `reason` (text) | rights · 권한 부여 |
| `STP5200U03` | 권한 회수 | `user_id` (text), `right_code` (text), `account_id` (text, 선택), `effective_from` (date, 선택), `reason` (text) | rights · 권한 회수 |

## 그리드 `users` 사용자

- 트랜잭션: `STP5200R01` → 데이터셋 `main`
- 불러오는 때: 화면 열 때 + 조회 버튼
- 상태 표시: 지금 사용자 (`user`)
- 실시간: DB가 바뀌면 마지막 조회조건으로 다시 조회, 바뀐 칸 강조 (행 식별 열 `user_id`)

| 열 | 한글명 | DB 컬럼 | DB 주석 | 형식 | 정렬 | 색 | 표시 |
|---|---|---|---|---|---|---|---|
| `user_id` | 사용자 ID | app_users.user_id | 사용자 ID (지금은 PC 로그인 이름) | 코드 | 왼쪽 |  |  |
| `name` | 이름 | app_users.name | 이름 | 문자 | 왼쪽 |  |  |
| `rights` | 지금 권한 | - | (화면 계산·집계 값) | 문자 | 왼쪽 |  |  |
| `created_by` | 등록한 사람 | app_users.created_by | 등록한 사람 | 문자 | 왼쪽 |  |  |
| `created_at` | 등록 시각 | app_users.created_at | 등록 시각 | 일시 | 왼쪽 |  |  |
| `me` | 나 | - | (화면 계산·집계 값) | 문자 | 왼쪽 |  | 숨김 (행 식별·연결에만 씀) |

- 위치: 그리드 오른쪽 위
