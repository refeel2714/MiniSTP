# STP-2210 기준가 변동 원인

> 이 문서는 `src/ministp/ui/screens/STP-2210.yaml`에서 생성돼요. 직접 고치지 말고 화면 정의를 고친 뒤 `python scripts/gen_screen_docs.py`를 실행하세요.

분류: 대사·평가 > 기준가

## 목적

하루 사이에 순자산이 왜 그만큼 바뀌었는지를 분개로 설명해요. 왼쪽에서 기준일을 고르면 오른쪽에 전일 순자산에서 당일 순자산까지를 위에서 아래로 읽는 표가 나와요. 순자산은 들고 있는 것(예수금, 미수·미지급, 보유수량 × 종가)에서 세고, 변동 원인은 그 사이에 기록된 분개(평가손익, 매매손익, 수수료, 세금, 입출금)에서 따로 더해요. 둘이 맞으면 설명되지 않은 차이가 0이에요. 0이 아닌 날이 있으면 그날이 먼저 골라져 있어요. 기준일을 두 번 누르면 그날의 분개를 분개 조회(STP-3200)에서 열어요.

## 화면 구성

좌우 구성이에요. 왼쪽 목록에서 행을 고르면 오른쪽이 그 행의 상세로 바뀌어요.

- 왼쪽 (너비 36%): `days` 기준일
- 오른쪽: `bridge` 변동 원인

## 트랜잭션

| 트랜잭션 | 이름 | 조회조건 | 쓰는 그리드 |
|---|---|---|---|
| `STP2210R01` | 기준일별 순자산 변동 | `date_from` (date), `date_to` (date) | days |
| `STP2210R02` | 기준일의 순자산 변동 원인 | `date` (date) | bridge |

## 그리드 `days` 기준일

- 트랜잭션: `STP2210R01` → 데이터셋 `main`
- 불러오는 때: 화면 열 때 + 조회 버튼
- 상태 표시: 모두 설명됨 (`all_explained`), 설명 안 된 날 수 (`unexplained_days`)
- 행 더블클릭·Enter: STP-3200로 이동 (`date_from` ← `date`, `date_to` ← `date`)
- 실시간: DB가 바뀌면 마지막 조회조건으로 다시 조회, 바뀐 칸 강조 (행 식별 열 `date`)

| 열 | 한글명 | DB 컬럼 | DB 주석 | 형식 | 정렬 | 색 | 표시 |
|---|---|---|---|---|---|---|---|
| `date` | 기준일 | - | (화면 계산·집계 값) | 날짜 | 왼쪽 |  |  |
| `change` | 순자산 변동 | - | (화면 계산·집계 값) | 금액 | 오른쪽 | 부호(+빨강/-파랑) |  |
| `unexplained` | 설명되지 않은 차이 | - | (화면 계산·집계 값) | 금액 | 오른쪽 | 부호(+빨강/-파랑) |  |
| `result` | 결과 | - | (화면 계산·집계 값) | 문자 | 왼쪽 | 상태 | 상태 표시(둥근 표시) |

## 그리드 `bridge` 변동 원인

- 트랜잭션: `STP2210R02` → 데이터셋 `main`
- 불러오는 때: 목록(마스터)에서 행 선택
- 마스터: `days` (`date` ← `days.date`)

| 열 | 한글명 | DB 컬럼 | DB 주석 | 형식 | 정렬 | 색 | 표시 |
|---|---|---|---|---|---|---|---|
| `kind` | 구분 | - | (화면 계산·집계 값) | 문자 | 왼쪽 |  |  |
| `code` | 계정코드 | accounts_chart.code | 계정코드 | 코드 | 왼쪽 |  |  |
| `name` | 계정명 | accounts_chart.name | 계정명 | 문자 | 왼쪽 |  |  |
| `amount` | 순자산에 준 영향 | - | (화면 계산·집계 값) | 금액 | 오른쪽 | 부호(+빨강/-파랑) |  |
| `running` | 순자산 누계 | - | (화면 계산·집계 값) | 금액 | 오른쪽 |  |  |
