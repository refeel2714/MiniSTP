# STP-5100 주문 결재

> 이 문서는 `src/ministp/ui/screens/STP-5100.yaml`에서 생성돼요. 직접 고치지 말고 화면 정의를 고친 뒤 `python scripts/gen_screen_docs.py`를 실행하세요.

분류: 운용 통제 > 주문 결재

## 목적

승인을 기다리는 요청을 체크해서 한 번에 승인하거나 반려해요(R-100, R-102). 오른쪽 "선택 묶음 검증"은 체크한 요청을 모두 함께, 이미 승인했지만 아직 안 나간 요청과 미체결 주문까지 더해서 다시 본 결과예요(R-98). 묶음이 불합격이거나 내 1건 승인 한도를 넘거나, 본인이 쓴 요청인데 셀프 승인 허용이 없으면 승인 버튼이 잠겨요. 바스켓(BK)처럼 묶음 번호가 같은 요청은 함께 체크되고 함께 승인·반려돼요. 승인해도 장중 `run`이 보내기 직전에 같은 계산을 한 번 더 해요. 요청 취소는 작성자만 해요.

## 화면 구성

좌우 구성이에요. 왼쪽 목록에서 행을 고르면 오른쪽이 그 행의 상세로 바뀌어요.

- 왼쪽 (너비 60%): `requests` 결재할 요청
- 오른쪽: `set` 선택 묶음 검증, `history` 결재·전송 이력

| 트랜잭션 | 이름 | 조회조건 | 쓰는 그리드 |
|---|---|---|---|

## 처리 트랜잭션

처리 버튼이 부르는 트랜잭션이에요. CLI 명령과 같은 함수를 부르고, 화면 서버를 처리 가능으로 열었을 때만 동작해요.

| 트랜잭션 | 이름 | 입력 | 부르는 버튼 |
|---|---|---|---|
| `STP5100U01` | 승인 | `picked` (text) | requests · 승인 |

| `STP5100U03` | 요청 취소 | `picked` (text), `reason` (text, 선택) | requests · 요청 취소 |

## 그리드 `requests` 결재할 요청

- 트랜잭션: `STP5100R01` → 데이터셋 `main`
- 불러오는 때: 조회조건을 바꿀 때마다 (입력 즉시 재계산)
- 높이 비중: 3 (좌우 구성에서 같은 쪽 그리드와 나눠 쓰는 높이)
- 체크박스: 행 앞의 체크박스로 여러 행을 골라요. 체크한 행의 키(`request_id`)를 쉼표로 이어 `picked`로 보내요(그 값을 받는 그리드는 체크를 바꿀 때마다 다시 계산). `pickable`이 참인 행만 체크할 수 있어요. `batch_id` 값이 같은 행은 함께 체크되고 함께 풀려요(묶음은 전부 아니면 전무). 머리의 체크박스는 모두 체크·해제, 행에서 스페이스로도 체크해요
- 상태 표시: 사용자 (`user`)
- 실시간: DB가 바뀌면 마지막 조회조건으로 다시 조회, 바뀐 칸 강조 (행 식별 열 `request_id`)

### 처리 버튼 `approve` 승인

- 위치: 그리드 오른쪽 위
- 처리 트랜잭션: `STP5100U01` 승인
- 대상: 행을 고르지 않아도 됨
- 안내: 체크한 요청을 승인해요. 서버가 권한(1건 한도, 셀프 승인)과 묶음 검증을 한 번 더 봐요. 장중이면 run이 보내기 직전에 다시 검증하고 보내요.
- 그리드가 채우는 입력: `picked` (체크한 행, 화면에서 쓴 줄)
- 잠금: 트랜잭션 `STP5100R01`의 상태값 `approve_lock`이 비어 있지 않으면 잠기고 그 글이 이유로 보여요. 서버는 누를 때 같은 검사를 다시 해요
- 입력 창: 입력 항목 없이 확인만 받아요
