# STP-4400 계좌 관리

> 이 문서는 `src/ministp/ui/screens/STP-4400.yaml`에서 생성돼요. 직접 고치지 말고 화면 정의를 고친 뒤 `python scripts/gen_screen_docs.py`를 실행하세요.

분류: 기준정보 > 계좌 관리

## 목적

등록된 위탁계좌의 기본정보예요. 기준정보라서 어느 계좌에 무엇이 얼마나 들어 있는지는 여기에 없어요. 예수금과 결제 예정은 계좌정보(STP-3400), 보유는 잔고(STP-1100)와 고객별 보유(STP-1400)에 있어요. 왼쪽에서 계좌를 고르면 오른쪽에 그 계좌의 상태 이력이 나와요. 화면을 열면 위쪽 막대에서 고른 계좌가 먼저 골라져 있고, 더블클릭하면 그 계좌의 계좌정보(STP-3400)로 가요. 계좌번호와 인증키는 DB에 없고 이 화면에도 나오지 않아요. 계좌 등록과 상태 변경은 위탁계좌 그리드 오른쪽 위 버튼으로 해요 (CLI의 account 명령과 같은 처리). 고객 등록은 고객별 보유(STP-1400)에서 해요.

## 화면 구성

좌우 구성이에요. 왼쪽 목록에서 행을 고르면 오른쪽이 그 행의 상세로 바뀌어요.

- 왼쪽 (너비 60%): `accounts` 위탁계좌
- 오른쪽: `status_history` 이 계좌의 상태 이력

## 트랜잭션

| 트랜잭션 | 이름 | 조회조건 | 쓰는 그리드 |
|---|---|---|---|
| `STP4400R01` | 계좌 목록 | 없음 | accounts |
| `STP4400R02` | 계좌 상태 이력 | `account_id` (text) | status_history |

## 처리 트랜잭션

처리 버튼이 부르는 트랜잭션이에요. CLI 명령과 같은 함수를 부르고, 화면 서버를 처리 가능으로 열었을 때만 동작해요.

| 트랜잭션 | 이름 | 입력 | 부르는 버튼 |
|---|---|---|---|
| `STP4400U01` | 계좌 등록 | `account_id` (text), `customer_id` (text), `alias` (text), `credential_ref` (text) | accounts · 계좌 등록 |
| `STP4400U02` | 계좌 상태 변경 | `account_id` (text), `status` (text), `effective_from` (date, 선택), `reason` (text) | accounts · 상태 변경 |

## 그리드 `accounts` 위탁계좌

- 트랜잭션: `STP4400R01` → 데이터셋 `main`
- 불러오는 때: 화면 열 때 + 조회 버튼
- 행 더블클릭·Enter: STP-3400로 이동 (계좌 ← `account_id`)
- 실시간: DB가 바뀌면 마지막 조회조건으로 다시 조회, 바뀐 칸 강조 (행 식별 열 `account_id`)

| 열 | 한글명 | DB 컬럼 | DB 주석 | 형식 | 정렬 | 색 | 표시 |
|---|---|---|---|---|---|---|---|
| `account_id` | 계좌 ID | trading_accounts.account_id | 계좌 ID | 코드 | 왼쪽 |  |  |
| `alias` | 계좌 별칭 | trading_accounts.alias | 계좌 별칭 | 문자 | 왼쪽 |  |  |
| `customer_alias` | 고객 별칭 | customers.alias | 고객 별칭 | 문자 | 왼쪽 |  |  |
| `status` | 현재 상태 | account_status_v.status | 현재 상태 | 코드 | 왼쪽 | 상태 | 코드명(공통코드 `ACCOUNT_STATUS`) |
| `broker` | 증권사 | trading_accounts.broker | 증권사 (KIS) | 코드 | 왼쪽 |  | 코드명(공통코드 `BROKER`) |

### 처리 버튼 `add` 계좌 등록

- 위치: 그리드 오른쪽 위
- 처리 트랜잭션: `STP4400U01` 계좌 등록
- 대상: 행을 고르지 않아도 됨
- 안내: 계좌번호와 인증키는 넣지 않아요. 인증정보 이름만 적고, 키는 이 PC의 환경변수(MINISTP_<이름>_APP_KEY 등)에 둬요. 지금은 모의투자 계좌만 등록해요.

| 입력 항목 | 한글명 | 형식 | DB 컬럼 | 필수 | 처음 값 | 선택값 | 찾기 팝업 |
|---|---|---|---|---|---|---|---|
| `account_id` | 계좌 ID | text | trading_accounts.account_id | 예 |  |  |  |
| `customer_id` | 고객 ID | text | trading_accounts.customer_id | 예 |  |  | `customer` |
| `alias` | 계좌 별칭 | text | trading_accounts.alias | 예 |  |  |  |
| `credential_ref` | 인증정보 참조 | text | trading_accounts.credential_ref | 예 |  |  |  |

### 처리 버튼 `status` 상태 변경

- 위치: 그리드 오른쪽 위
- 처리 트랜잭션: `STP4400U02` 계좌 상태 변경
- 대상: 고른 행
- 입력 창 위에 보여 주는 행의 값: `account_id`, `alias`, `status`
- 안내: 상태는 고치지 않고 이력에 새 행으로 덧붙여요. 해지는 예수금·보유·미결제가 모두 0일 때만 되고, 해지한 계좌는 다시 열지 않아요.

| 입력 항목 | 한글명 | 형식 | DB 컬럼 | 필수 | 처음 값 | 선택값 | 찾기 팝업 |
|---|---|---|---|---|---|---|---|
| `account_id` | 계좌 ID | text | trading_accounts.account_id | 예 | 행의 `account_id` (고칠 수 없음) |  |  |
| `status` | 상태 | text | account_status_history.status | 예 |  |  | `code` (group_id=ACCOUNT_STATUS) |
| `effective_from` | 적용 시작일 | date | account_status_history.effective_from |  | today |  |  |
| `reason` | 사유 | text | account_status_history.reason | 예 |  |  |  |

## 그리드 `status_history` 이 계좌의 상태 이력

- 트랜잭션: `STP4400R02` → 데이터셋 `main`
- 불러오는 때: 목록(마스터)에서 행 선택
- 마스터: `accounts` (`account_id` ← `accounts.account_id`)

| `effective_from` | 적용 시작일 | account_status_history.effective_from | 적용 시작일 | 날짜 | 왼쪽 |  |  |
| `reason` | 사유 | account_status_history.reason | 사유 | 문자 | 왼쪽 |  |  |

## 찾기 팝업

입력 칸 옆 찾기 버튼(또는 F2)으로 여는 목록이에요. 여러 화면이 같은 정의(`lookups.yaml`)를 같이 써요.

| 이름 | 제목 | 조회 트랜잭션 | 고르면 들어가는 열 | 함께 보여 주는 열 | 목록의 열 |
|---|---|---|---|---|---|
| `code` | 코드 찾기 | `STP4600R02` | `code` | `name` | 코드(`code`), 코드명(`name`), 코드 설명(`description`), 사용 여부(`in_use`) |
| `customer` | 고객 찾기 | `STP1400R01` | `customer_id` | `alias` | 고객 ID(`customer_id`), 고객 별칭(`alias`), 계좌 수(`accounts`) |
