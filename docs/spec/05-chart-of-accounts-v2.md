# 05. 계정과목표 v2: 법인 장부 기준 (제안, 2026-11-24)

> 상태: **초안에 적용** (2026-11-25, 스펙 v1.45, ERD v2.13 `0013_chart_v2`). 운영 DB는 게이트(대사 20영업일 연속 일치) 뒤 머지할 때 바뀐다. 세무 확인 표의 세율과 "확인 요청"의 이름은 아직 확인 전이라, 이름은 이 문서의 제안대로 두고 원천징수 세율(R-23)은 바꾸지 않았다.
>
> 적용하며 정한 것: (1) 5050 사용 중지는 `accounts_chart.in_use` 열과 DB 트리거(`ministp_account_in_use`, 새 분개 줄 거부)로. (2) 분배금수익은 종목의 자산 유형이 ETF이면 쓴다. (3) 선납세금은 회사의 자산이지만 증권계좌 밖이라 순자산·기준가(R-60)에 넣지 않는다. 기준가 이력(STP-2210)은 이를 "선납세금"으로 나간 변동으로 설명한다. (4) 공통코드 설명 중 옛 계정 이름을 적은 일곱 개를 새 이름으로 고쳤다.

## 왜 고치나

계정과목표 v1(D4)은 "투자자 관점의 FVPL 회계"로 만들었지만, 계좌 하나를 펀드처럼 보는 틀이었다. D9로 장부의 주인이 **법인**이 되면서, 회계 담당자가 이 전표를 회사 장부에 그대로 옮겼을 때 틀리는 곳이 세 군데 있다. 계정을 늘리는 일보다 이 세 곳을 법인 기준으로 고치는 일이 먼저다.

| v1 계정 | 법인 장부에서 문제 | v2 |
|---|---|---|
| 3010 투자원금 (자본) | 법인이 증권계좌에 돈을 넣는 것은 자본 거래가 아니다. 회사 장부에서는 보통예금(은행)에서 증권계좌로 옮긴 **자산 사이의 이체**다. | 이름과 성격을 "본사 자금 대체"로 바꾼다. 코드는 그대로. |
| 5050 법인세등(원천징수) (비용) | 법인이 원천징수당한 세금은 비용이 아니라 **선납세금(자산)**이다. 결산 때 그해 법인세에서 뺀다. | 새 자산 계정 1040 선납세금으로 옮기고, 5050은 더 쓰지 않는다. |
| 1010 예수금 | 회사 장부에서 "예수금"은 **부채**(남에게 받아 둔 돈, 예: 급여 원천세)다. 증권사가 부르는 이름이라 회계 담당자가 헷갈린다. | 이름을 "증권예치금"으로. 대사와 증권사 화면에서는 증권사 용어 "예수금"을 그대로 쓴다. |

## 원칙

1. **계정은 "어떤 성격의 돈인가"만 말한다.** 종목, 증권계좌, 증권사는 계정으로 쪼개지 않고 전표 줄의 **관리항목**으로 붙인다. ERP의 보조원장(관리항목, 거래처)과 같은 방식이다. 종목이 100개, 증권사가 3곳이어도 계정 수는 그대로다. (D4 채번 규칙 2번과 같은 원칙)
2. **성격이 다를 때만 나눈다.** 기준은 "회계 처리나 세무 처리가 다른가"다. ETF 분배금은 주식 배당과 원천징수 여부, 익금불산입 대상 여부가 달라서 나눈다. 주식과 ETF의 취득원가는 회계 처리가 같아서 나누지 않는다(종목유형은 관리항목).
3. **한 번 쓴 코드는 바꾸지 않는다.** 전표는 고칠 수 없으므로(R-04) 코드의 뜻을 바꾸지 않는다. 이름은 고칠 수 있다. 성격이 바뀌는 계정(5050)은 새 코드를 만들고 옛 코드는 "사용 중지"로 둔다.
4. **회사 계정코드로 바꾸는 일(매핑)은 선택이다.** MiniSTP는 이 표를 기준으로 쓴다. 실제 도입 때만 매핑 파일(R-96)로 회사 코드에 맞춘다.
5. **결산은 ERP가 한다.** MiniSTP는 손익 계정을 연도별로 닫지 않는다. 법인세비용, 이연법인세, 수입배당금 익금불산입 같은 세무조정은 ERP와 세무 담당의 몫이다.

### 3010 "본사 자금 대체"를 어떻게 읽나

지점 회계의 본지점 계정과 같다. MiniSTP는 회사 장부 전체가 아니라 **증권계좌 한 칸**만 맡은 보조 장부다. 회사 은행계좌는 MiniSTP 밖에 있으므로, 돈이 들어오고 나가는 상대편을 3010 한 계정에 모은다.

- MiniSTP 안에서는 v1과 똑같이 기준가·좌수의 분모(넣은 돈)로 쓴다. NAV 계산은 바뀌지 않는다.
- ERP로 내보낼 때는 이 줄이 회사의 보통예금(또는 회사가 정한 자금이체 계정)이 된다. 매핑이 없으면 "3010 본사 자금 대체"로 나가고, 회계 담당자가 은행 쪽 계정으로 바꿔 올린다. 매핑이 실제로 필요한 계정은 사실상 이것 하나다.
- 원장 시작 때(R-05) 넘겨받은 예수금과 보유 종목도 3010으로 받는다. 이 잔고는 이미 회사 장부에 있으므로 **ERP로 다시 보내면 두 번 잡힌다.** 아래 "후속 작업"의 1번.

## ERP와 맞추는 방법 (3자 대사, D9 더할 것 4)

MiniSTP는 연도 마감을 하지 않으므로, ERP와 맞출 때 계정 성격에 따라 비교하는 값이 다르다.

- 자산·부채(1xxx, 2xxx): **잔액**을 비교한다. 단, 선납세금(1040)은 ERP가 결산 때 법인세와 상계하므로, 그해 발생액으로 비교한다.
- 수익·비용(4xxx, 5xxx): **기간 발생액**(월·연)을 비교한다.
- 본사 자금 대체(3010): ERP의 증권계좌 이체 합계와 비교한다.

## 후속 작업 (게이트 전에 할 수 있음, DB 안 바꿈)

1. **기초 잔고 전표는 ERP로 보내지 않기**: 원장 시작(R-05)의 입금·기초 보유 전표는 이미 회사 장부에 있는 잔고다. `erp export`가 이 전표를 빼거나 "기초 이월"로 따로 표시한다.
2. **CSV에 관리항목 열**: 종목코드, 종목명, 증권계좌를 줄마다 붙인다.
3. **매핑 예시 파일 갱신**: 이 문서가 확정되면 `docs/erp/mapping.example.yaml`의 주석을 v2 이름에 맞춘다.

## 확인 요청 (리필)

1. 1010 이름을 "증권예치금"으로 바꿔도 되는지. 화면의 대사 항목은 증권사 용어 "예수금"을 그대로 둔다.
2. 3010 이름을 "본사 자금 대체"로. 다른 이름(예: "투자자금 대체", "본점")이 회사에서 더 익숙하면 그걸로.
3. 세무 확인 표의 세율은 세무 담당 확인 전까지 "확인 필요"로 둔다.
